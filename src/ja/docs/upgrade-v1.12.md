# v1.12 へのアップグレード

v1.12 ではデータの移行は不要です。v1.11 で書き出したダンプは変換せずに読み込めます。TCP と HTTP のインターフェースも変わりません。ただし、これまで起動できた設定のうち 2 つが拒否されるようになりました。v1.11 より前から更新する場合は、先に [v1.11 のアップグレード手順](/ja/docs/upgrade-v1.11)を実施してください。

## バイナリログが有効か確認する

ソースは `log_bin=ON` で動いている必要があります。バイナリログが無効なサーバーには、読み取る binlog がありません。MygramDB は起動時と再接続時にこれを `2008` で拒否します。ほかの[ソース要件](/ja/docs/replication#%E3%82%BD%E3%83%BC%E3%82%B9%E3%81%A8%E3%83%86%E3%83%BC%E3%83%95%E3%82%99%E3%83%AB%E3%81%AE%E6%A4%9C%E8%A8%BC)を満たさない場合と同じ扱いです。

稼働中のサーバーで確認します。

```sql
SELECT @@GLOBAL.log_bin;
```

`1` なら有効です。MySQL ではデフォルトで有効ですが、MariaDB では無効です。`log_bin` は実行中に変更できないため、サーバー設定で有効にしてソースを再起動してください。

```ini
[mysqld]
log_bin = mysql-bin
```

## `replication.start_from` を確認する

`gtid=,` のように区切り文字しかない `gtid=` の値は、設定エラーになります。実際の位置を指定するか、`snapshot` または `latest` を使ってください。稼働中のノードを置き換える前に設定ファイルを検証します。

```bash
mygramdb -t /etc/mygramdb/config.yaml
```

## 新たに使えるようになったもの

- **タグ付き GTID。** `gtid_executed` にタグ付きのエントリ（`UUID:tag:txn`）を持つ MySQL 8.4 以降のソースは、これまで `2005` で拒否されていました。現在は起動でき、変更を取り込み、再接続後も続きから再開します。開始位置に単独の `UUID:tag:N` を書くと「N まで」を意味し、`UUID:tag:1-N` に広げられます。`UUID:N` が `UUID:1-N` に広げられるのと同じです。詳しくは [`gtid=<position>`](/ja/docs/replication#start-from-gtid) を参照してください。
- **MySQL 26.x。** Innovation リリースに対応し、LTS の 8.4 系・9.7 系と並ぶ対応バージョンになりました。binlog 形式、GTID のエンコード、必須設定は 9.7 と同じです。

## 行デコードの厳格化

binlog イベントのデコードは libmybinlog が担当するようになりました。ほかの binlog ツールと共有する独立したライブラリです。binlog からデコードした行の値は、初期スナップショット経由と同じ文字列で表現されます。

これまで推測でデコードしていた不正な入力は拒否されます。次のいずれかを含む行イベントは失敗として扱います。

- 長さ 0 バイトの BLOB 長プレフィックス
- ENUM/SET のパック長 0
- パック整数の `0xFB`/`0xFF`
- カラム数 0

トランザクション番号が 0 または `INT64_MAX` の GTID イベントは、デコードできないイベント（`2017`）として扱います。正常なソースはこうしたイベントを書かないため、binlog の破損が疑われます。`2017` でレプリケーションが停止した場合は、[デコードできない binlog イベントからの復旧](/ja/docs/replication#%E3%83%86%E3%82%99%E3%82%B3%E3%83%BC%E3%83%88%E3%82%99%E3%81%A6%E3%82%99%E3%81%8D%E3%81%AA%E3%81%84-binlog-%E3%82%A4%E3%83%98%E3%82%99%E3%83%B3%E3%83%88%E3%81%8B%E3%82%89%E5%BE%A9%E6%97%A7%E3%81%99%E3%82%8B)の手順に従ってください。

圧縮されたトランザクションイベントと `PARTIAL_UPDATE_ROWS` は、引き続き未対応です。

## ソースからのビルド

ビルドには CMake 3.18 以降が必要になり、libmybinlog を GitHub から取得します。オフラインでビルドする方法は[ソースからビルド](/ja/docs/installation#%E3%83%92%E3%82%99%E3%83%AB%E3%83%88%E3%82%99)を参照してください。

## クライアントライブラリを更新する

v1.12 に対応するクライアントのリリースは、`mygramdb-client` 1.7.0（Node.js）、`mygramdb-client` 1.6.0（Python）、`go-mygram-client` v0.7.0（Go）です。応答はサーバーの文法が定める終端まで読み取り、Web 構文の検索式はサーバーと同じ規則でグループ化して変換します。たとえば `a OR b c` は `(a OR b c)` になります。解析済みの `SearchExpression` からは、常に空だった `optionalTerms` フィールドが削除されました。詳しくは[クライアントライブラリ](/ja/docs/client-libraries)を参照してください。

## 更新チェックリスト

1. ソースで `SELECT @@GLOBAL.log_bin;` が `1` を返すことを確認する。
2. `mygramdb -t` で本番設定を検証し、区切り文字しかない `gtid=` の値があれば置き換える。
3. ソースからビルドする場合は、CMake 3.18 以降があることを確認する。
4. アプリケーションのクライアントを Node.js 1.7.0、Python 1.6.0、Go v0.7.0 に更新し、`optionalTerms` を使っている箇所を取り除く。
5. 再起動後に ready になるまで待ち、レプリケーションが進むことを確認する。`2017` で停止した場合は、binlog の破損を調べる。

変更の全体は [v1.12.0 リリースノート](https://github.com/libraz/mygram-db/blob/main/docs/releases/v1.12.0.md)を参照してください。
