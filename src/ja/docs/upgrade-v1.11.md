# v1.11 へのアップグレード

::: info 現行リリースへ更新する場合
[v1.12 のアップグレード手順](/ja/docs/upgrade-v1.12)も実施してください。ソースは `log_bin=ON` で動いている必要があり、開始位置としての `gtid=,` は受け付けなくなりました。
:::

実行中のノードを置き換える前に、ソースで完全な行メタデータを有効にし、ソースとテーブルの要件を確認してください。ネイティブクライアントの再ビルドと監視の認証設定も必要です。v1.10.2 より前から更新する場合は、[以前のアップグレード手順](/ja/docs/upgrade-v1.10)も実施してください。

## 現行パッチの確認事項

ロールアウト前に次の動作変更を確認してください。

| 変更 | 対応 |
| --- | --- |
| `0.0.0.0/0` と `::/0` は、どちらも IPv4 と IPv6 の接続元を許可します。 | IPv4 だけを許可するつもりだった場合は、`network.allow_cidrs` を狭めます。[ネットワークセキュリティ](/ja/docs/configuration)を参照してください。 |
| `api.unix_socket.path` に通常ファイルがあると起動を拒否し、そのファイルは残ります。 | ファイルを移動するか、別のパスを選びます。[API サーバー設定](/ja/docs/configuration)を参照してください。 |
| `--schema` で指定したカスタム JSON Schema は、実行時の `SET` にも適用されます。 | 現在のルールを[運用ガイド](/ja/docs/operations)で確認します。 |
| 設定済みの全テーブルで初期ロードが完了するまで、`DUMP SAVE` は `6029` を返します。 | ノードが ready になってから保存します。認証が必要な CLI の実行方法は、[スナップショットとダンプ復旧](/ja/docs/snapshot)を参照してください。 |
| 各 `primary_key` には、単独カラムの `PRIMARY KEY` または `UNIQUE NOT NULL` 制約が必要です。条件を満たさない定義は、初期スナップショットの前に拒否されます。 | キーの定義を確認します。[レプリケーション要件](/ja/docs/replication)を参照してください。 |

## binlog の完全な行メタデータを有効にする

MygramDB は、カラム名、符号の有無、`ENUM`/`SET` のラベルを binlog の各 `TABLE_MAP` イベントから読み取ります。これにより、イベントが書かれた時点のスキーマで行をデコードできます。ソースでは、従来の `ROW` 形式と `FULL` 行イメージに加えて、`binlog_row_metadata=FULL` が必須です。

MySQL では、次の設定を実行すると再起動後も維持されます。

```sql
SET PERSIST binlog_row_metadata = FULL;
```

MariaDB では、稼働中のサーバーに設定したうえで、再起動後も有効になるようサーバー設定ファイルにも追加します。

```sql
SET GLOBAL binlog_row_metadata = FULL;
```

```ini
[mysqld]
binlog_row_metadata = FULL
```

起動時と再接続時の検証は、別の値を `2008` で拒否します。設定を変更しても、古い binlog は書き換わりません。監視対象テーブルの `TABLE_MAP` に必要なメタデータがないと、レプリケーションは `2017` で停止します。ダンプから復元した再開位置など、再生範囲に古いイベントが残っている場合は、設定変更後にすべてのレプリケーション対象テーブルへ `SYNC <table>` を実行してください。`SYNC STATUS` で完了を確認してから、次のテーブルを処理します。

## ソースとテーブルを確認する

ソース設定の全体は[レプリケーションの要件](/ja/docs/replication)を参照してください。更新前に次の条件を確認します。

| 条件 | 必要な対応 |
| --- | --- |
| ソース自体がレプリカ | MySQL では `log_replica_updates`、MariaDB では `log_slave_updates` を有効にします。MySQL の接続アカウントには `SHOW REPLICA STATUS` 用の `REPLICATION CLIENT` 権限が必要です。 |
| MariaDB が `binlog_storage_engine` を使用 | エンジン統合型 binlog を使わないソースにします。この方式には、必要なイベント単位のチェックサムがありません。 |
| 監視対象テーブルが、更新または削除時に `CASCADE`、`SET NULL`、`SET DEFAULT` を実行する外部キーの子テーブル | 子の各行の変更が binlog に記録されるスキーマにします。MySQL 9.0 以降で `innodb_native_foreign_keys=OFF` の場合は例外です。 |
| 設定したキーに独立した単一カラムの一意制約がない、または単一カラムの一意制約が `NULL` を許可 | 単一カラムの `PRIMARY KEY` または `UNIQUE NOT NULL` キーを使います。 |
| MariaDB のいずれかのカラムが、`n > 0` の旧形式の `TIME(n)`、`DATETIME(n)`、`TIMESTAMP(n)` | `ALTER TABLE ... MODIFY` でカラムを再構築します。`SHOW COLUMNS` に `/* mariadb-5.3 */` と表示される形式が対象です。 |
| 設定したカラムが `year(2)` | 対応するカラム型へ変更します。 |
| ソースが `lower_case_table_names=0` | 設定内のデータベース名とテーブル名を、ソースの名前とバイト単位で一致させます。ほかの値では、行イベントと DDL のどちらも ASCII の大文字・小文字を区別しません。 |

ソースの要件は初期スナップショット前と再接続時に、テーブルの要件は起動時と DDL 後に検証します。テーブルの内容を置き換えるパーティション操作やテーブルスペース操作、`CREATE OR REPLACE TABLE` では、レプリケーションが `2017` で停止します。変更を解決してから `SYNC` で再構築してください。ソースの `1236` エラーで `SYNC` が必要なのは、メッセージが必要な GTID の削除を示す場合です。それ以外の `1236` は、ソースの診断メッセージを保持した `2008` で停止します。

## 設定と行サイズを検証する

正常なノードを止める前に、本番用の設定ファイルを検証します。

```bash
mygramdb -t /etc/mygramdb/config.yaml
```

このコマンドはファイルを検証します。起動時のソースとテーブルの検証は別途行われます。次の制約を確認してください。

- レプリケーションを有効にする場合、`replication` ブロックを省略していても、ゼロ以外の `replication.server_id` が必要です。
- `replication.start_from: gtid=...` には、有効な MySQL GTID セットまたは MariaDB の `domain-server-seq` リストを指定します。`UUID:N` は N までの全トランザクションを表します。MySQL のトランザクション番号は 2^63−1 未満にします。
- `network.allow_cidrs` に IPv4 射影 IPv6 アドレス（IPv4-mapped IPv6）を書く場合、プレフィックス長は 96 以上にします。
- `memory.hard_limit_mb` と `memory.soft_target_mb` は、現在は予約済みの設定ですが、値は `2147483647` 以下にします。
- 実行時の `SET` も設定スキーマに従います。不正な値は `1004` を返し、複数代入はすべてを適用するか、すべてを取り消します。

初期スナップショットの読み込み、`SYNC`、レプリケーションには、ダンプと同じドキュメント上限が適用されます。

| 項目 | 上限 |
| --- | --- |
| 主キー | 1 MiB |
| ドキュメントあたりのフィルタ数 | 1,000 個 |
| フィルタ名 | 1 KiB |
| 文字列フィルタ値 | 64 KiB |
| 正規化テキストと元テキスト | それぞれ 16 MiB |

上限を超える行があると、読み込みや `SYNC` は失敗します。レプリケーション中は、GTID を進めずにエラーを報告します。復旧前にソースのデータまたは設定を修正してください。

## C/C++ クライアントを再ビルドする

ネイティブ共有ライブラリは `libmygramclient.so.2`、ライブラリのバージョンは `2.0.0` です。インストールしたヘッダーとライブラリを組み合わせて、C/C++ プログラムを再ビルドしてください。

- `SearchExpression` に `required_is_group` と `excluded_is_group` が加わり、`optional_terms` は削除されました。
- `MygramParsedExpression_C` の `optional_terms` と `optional_count` は削除されました。

詳しくは[ネイティブクライアントのリファレンス](/ja/docs/client-library)を参照してください。これはネイティブ構造体のレイアウト変更による更新です。ライブラリのバージョンは、サーバーのリリース番号とは別に管理されます。

## レプリケーション監視に認証を設定する

`api.admin_token` を設定すると、TCP の `INFO` は接続が `AUTH` を完了するまで `# Replication` セクションを省略します。HTTP の `/metrics` は、リクエストに `Authorization: Bearer <token>` がなければ、すべての `mygramdb_replication_` メトリクスを省略します。どちらも、ほかの統計は認証なしで取得できます。

保護された値の欠落をレプリケーション障害と誤認しないよう、更新前に監視の認証を設定してください。Prometheus の認証設定は [HTTP API ガイド](/ja/docs/http-api)を参照してください。

HTTP クライアントは、次の応答にも対応させてください。

| リクエスト | 応答 |
| --- | --- |
| 複数データベースの設定で、修飾なしのテーブル名を使う | `404` / `4007` |
| レプリケーションリーダーのない MySQL 対応ビルドへの `GET /replication/status` | `200` と `{"enabled":false,"status":"not_configured"}` |
| 設定が読み込まれていない状態での `GET /config` | `503` / `6026` |
| 上限を超える検索パラメータ | TCP と同じ `3000` |

## 更新後の動作を確認する

再起動後に ready になったことと代表的な検索を確認します。さらに、ソースへ書き込みながら、認証付きでレプリケーションの状態を確認します。ダンプ形式は変わらず、v1.10.2 のダンプは変換なしで読み込めます。ただし、再開位置が完全な行メタデータを持たないイベントを指す可能性は残ります。必要な `SYNC` が終わったら、[スナップショットコマンド](/ja/docs/snapshot)で新しいダンプを作成し、検証してください。

`used_memory_index` は、検索語ごとのオブジェクトとマップの管理領域も含みます。そのため、`OPTIMIZE` と `DUMP SAVE` に必要な空きメモリが従来の報告値より増える場合があります。`mygram-cli DUMP SAVE` は、最後の空でないトークンをパスとして扱います。空白を含むパスは引用符で囲み、未対応の `-` フラグは削除してください。

変更の全体は [v1.11.1 リリースノート](https://github.com/libraz/mygram-db/blob/main/docs/releases/v1.11.1.md)を参照してください。
