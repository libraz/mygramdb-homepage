# MySQL FULLTEXTが遅い理由

MySQL FULLTEXT の性能はクエリ、データ、メモリ、同時実行数に左右されます。公開ベンチマークでは、同じデータセットで MygramDB と比較しています。

## 何が問題なのか

MySQL は SQL の実行経路と InnoDB バッファプールを通して FULLTEXT クエリを処理します。MygramDB は別の検索インデックスをメモリに保持します。計測時の MySQL のバッファプールヒット率は 99.9989% であり、毎回ディスクを読んだ結果ではありません。

### クエリごとの処理

MySQL FULLTEXT は InnoDB 内の転置インデックスを使います。処理量は一致するポスティング、取得する行、ソート、インデックスページのバッファプールへの常駐状況で変わります。MygramDB はメモリ上のポスティングリストを交差し、必要に応じてテキストを照合して結果を返します。どちらも一定のクエリコストを仮定せず、各クエリの実測値をベンチマークで確認してください。

::: info 用語補足
**ポスティングリスト**は「この語を含むドキュメントIDの一覧」です。全文検索は、この一覧同士をAND/ORで組み合わせて候補を探します。詳しくは[用語集](/ja/docs/glossary#%E3%83%9B%E3%82%9A%E3%82%B9%E3%83%86%E3%82%A3%E3%83%B3%E3%82%AF%E3%82%99%E3%83%AA%E3%82%B9%E3%83%88)を参照してください。
:::

### キャッシュの影響

公開ベンチマークでは MySQL のバッファプールが温まった状態で、MygramDB のクエリキャッシュを無効にしています。どちらもキャッシュのヒットでレイテンシが変わり得るため、自分の計測結果と比べる際は条件を確認してください。

### 並列アクセス

1・2・4・8・16接続のキャッシュ無効時の結果と測定条件は、[ベンチマーク](/ja/benchmarks)に集約しています。負荷時のスループットとレイテンシはホストやワークロードによって変わります。

## 解決策：MygramDB

MygramDB は検索用に別の実行経路を提供します。

### 検索インデックスをメモリ上に保持

検索インデックスと保存するドキュメントデータはメモリに保持されます。検索時に MySQL FULLTEXT のインデックスページを読みません。

### 圧縮されたポスティングリスト

`OPTIMIZE` はポスティングリストの密度に応じてデルタエンコーディングかRoaring ビットマップを選びます。挿入時は4,096件を超えたデルタ形式のリストもRoaringへ変換します。メモリ使用量はデータに依存するため、[容量見積もり](/ja/docs/performance#_1-%E3%83%A1%E3%83%A2%E3%83%AA%E3%82%B5%E3%82%A4%E3%82%B7%E3%82%99%E3%83%B3%E3%82%AF%E3%82%99)を参照してください。

### SIMD命令で高速化

ビルドと CPU が対応する場合、Roaring ビットマップ演算は SIMD 命令を使用できます。

### メモリ上の検索インデックス

検索インデックスをメモリ上に保持するため、検索時に MySQL の FULLTEXT インデックスを読みません。MygramDB のクエリキャッシュを有効にするとレイテンシも変わります。キャッシュを無効にした実測値は[ベンチマーク](/ja/benchmarks)をご覧ください。

### MySQL / MariaDBのbinlogに追従

GTID ベースの binlog レプリケーションで、MySQL 8.4/9.x または MariaDB 10.11+/11.x/12.x の変更を反映します。検索用の ETL ジョブは不要ですが、MySQL のレプリケーション設定、初期スナップショットまたは `SYNC`、検索リクエストの転送先変更が必要です。反映遅延は MySQL 側の負荷、ネットワーク、MygramDB の処理状況によって変わります。

::: info 用語補足
**ETL** はデータを抽出（Extract）し、変換（Transform）し、別システムへ投入（Load）する仕組みです。MygramDBはMySQLのbinlogを直接読むため、検索用の同期ジョブを別途作る必要がありません。
:::

## 導入を検討するケース

- インデックス対象のデータが、プロセスやインデックス作成の余裕を含めて利用可能な RAM に収まる。
- 検索の読み取り負荷が MySQL の負担になっており、アプリケーションから MygramDB の API を呼び出せる。
- 実データと実際のクエリで測定した MySQL のレイテンシやスループットが、目標に届かない。
